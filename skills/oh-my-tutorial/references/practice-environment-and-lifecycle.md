# 연습 환경과 생명주기

## 먼저 결정할 사항

튜토리얼은 같은 목표를 반복 학습할 수 있어야 한다. 이를 위해 준비 상태와 변경 소유권을 정한다. 모든 도메인에 예시 데이터나 원복 기능이 필요한 것은 아니다.

| 방식 | 적합한 상황 | 확인할 사항 |
|---|---|---|
| 준비된 예시 | 안정적인 입문 흐름과 결과 비교 | 가용성, 초기 상태, 개인별 수정 범위 |
| 임시 연습 데이터 | 생성·수정의 실제 체험 | 세션 식별, 생성·정리 범위 |
| 현재 작업 | 실제 맥락에서 기능 연습 | 변경 유지 여부, 기존 미저장 변경 |
| 설명·시뮬레이션 | 실제 실행이 곤란한 기능 | 실제 기능과의 차이, 표시 일관성 |
| 조회·비교 | 데이터 변경이 필요 없는 학습 | 조건과 조회 맥락, 최신 결과 |

가능하면 기존 데모·테스트 기능을 활용한다. 프런트엔드 튜토리얼을 위해 불필요한 백엔드 설정 시스템을 만들지 않는다. 반대로 서버 기능이 꼭 필요한데 프런트엔드 모사만으로 실제 처리까지 완성됐다고 보고하지 않는다.

## 변경 소유권

다음 내용을 정한다.

```text
연습 방식:
준비할 자원과 준비 완료의 근거:
기존 사용자 데이터·미저장 작업에 미치는 영향:
튜토리얼이 생성·수정하는 자원:
유지할 변경 / 정리할 변경:
종료·재시작·준비 실패 시 처리:
취소할 수 없는 실행의 실제 상태:
```

식별 가능한 연습 자원만 정리한다. 전체 저장소를 스냅샷으로 덮어쓰면 튜토리얼과 무관한 변경을 잃을 수 있다. 현재 작업에서 원복을 제공하려면 기능의 기존 undo·트랜잭션·버전 확인을 활용하거나 격리된 사본을 선택한다.

공유 예시 데이터는 여러 사용자에게 보일 수 있다. 한 사용자의 튜토리얼이 다른 사용자에게 필요한 원본을 변경하거나 삭제하지 않게 한다. 사용자별 수정이 필요하면 로컬 상태나 사용자별 사본을 활용한다.

## 시작

1. 필요한 데이터·권한·기능이 실제로 준비될 수 있는지 확인한다.
2. 현재 미저장 작업에 영향을 주는지 확인하고 기존 제품의 보호 흐름을 존중한다.
3. 해당 연습에 필요한 자원과 상태만 준비한다.
4. 새 학습 세션을 식별하고 초기 단계에 진입한다.
5. 준비 완료를 확인한 뒤 첫 조작을 허용한다.

준비 실패 시 부분적으로 생성된 연습 자원을 정리하고 재시도·종료 경로를 제공한다. 사용할 수 없는 학습은 시작 전 가용 조건을 알려주는 것이 낫다.

## 진행

서로 다른 세션이나 작업의 결과를 섞지 않는다. 결과가 다른 화면에 있으면 그 화면까지 실제 맥락을 전달한다.

필요한 화면 이동·로딩은 준비 상태로 다룬다. 스텝 설명이 먼저 표시되더라도 실제 대상이 준비되지 않았다면 수행을 요구하지 않는다. 준비를 기다리는 동안 종료할 수 있어야 한다.

네트워크 지연이나 실패는 기존 오류 처리를 우선 활용한다. 튜토리얼을 진행시키기 위해 실패를 성공으로 변환하지 않는다.

## 종료와 정리

안내 UI 제거, 학습 세션 종료, 업무 작업 취소는 각각 다른 결정이다. 화면 이동·컴포넌트 제거 시에는 그 화면의 강조·리스너·대기를 정리한다. 학습까지 종료할지 같은 세션으로 이어갈지는 제품의 사용 흐름에 맞춰 정한다. 화면 밖에서도 진행되는 업무 작업의 상태 저장·이력 갱신을 튜토리얼의 단계 이탈 검사로 막지 않는다. 이어가기를 제공하면 같은 작업 ID의 최신 상태를 읽고 안내를 복구하며, 업무 실행을 다시 요청하지 않는다.

실제로 세션을 끝내는 경로에서는 해당 세션이 소유한 책임을 정리한다.

- 학습 완료, 사용자의 종료, 종료로 정한 화면 이탈.
- 준비 실패, 실행 실패 후 포기, 다른 학습으로 전환.
- 새로고침과 브라우저 뒤로 가기는 정한 종료·복귀 정책에 맞게 처리.

정리할 수 있는 항목:

- 이벤트 리스너·구독·타이머·대기 작업.
- 조작 제한, 강제 팝업, 임시 도구 상태.
- 튜토리얼이 만든 임시 자원.
- 튜토리얼이 이동시킨 포커스와 필요한 경우 복귀 위치.

정리 함수는 여러 번 호출돼도 무해하도록 한다. 준비 도중 종료했다면 나중에 준비가 완료돼도 세션을 다시 시작하지 않는다. 비동기 작업의 취소가 불가능하면 늦은 결과의 소유권을 확인해 종료된 학습을 전환시키지 않고, 정리 정책에 따른 소유 자원만 처리한다. 공유 업무 저장소나 다른 화면의 구독까지 해제하지 않는다.

## 현재 작업에서 연습할 때

현재 작업을 사용하는 것이 학습에 유리할 수 있다. 이 경우 다음을 명확히 한다.

- 연습 조작이 현재 작업에 반영되는가?
- 종료하면 변경이 유지되는가?
- 실행 중인 도구나 선택 상태만 정리하는가?
- 실제 저장은 기존 저장 흐름을 따르는가?

현재 작업에서 연습한다고 하면서 실제로 사본을 사용하는 것처럼 설명하거나, 변경을 유지하면서 자동 원복된다고 설명하지 않는다. 기존 미저장 작업을 튜토리얼 준비 목적으로 초기화하지 않는다.

### 조회 전용 화면의 복귀 예시

조회 연습은 업무 데이터를 수정하지 않더라도 필터, 선택, 표시 결과, 로딩 상태를 바꿀 수 있다. “데이터를 수정하지 않으므로 정리할 것이 없다”고 가정하지 않는다.

분석 화면에서 이전 맥락으로 복귀시키기로 했다면 해당 화면의 필터와 표시 결과를 작은 범위로 캡처한다. 입력 필터와 결과의 조회 조건이 다를 수 있으므로 둘을 구분해 보존한다. 기존 결과를 다시 조회해 복귀시킬지, 유효한 표시 상태를 복구할지 프로젝트에 맞춰 선택한다.

시작·종료·재시작 시 이전 조회 응답이 복구한 화면을 뒤늦게 덮어쓰지 않도록 요청 소유권과 화면의 버전 처리를 연결한다. 캡처한 로딩 표시를 복구할 때는 실제 대기 중인 요청이 있는지도 확인한다. 종료된 요청을 계속 기다리는 화면으로 복구하지 않는다.

복구 범위는 튜토리얼이 소유한 조회 맥락으로 한정한다. 다른 작업의 선택이나 갱신을 덮어쓰지 않으며, 결과의 유효성이 달라졌다면 기존 화면의 재조회 규칙을 따른다.

## 시뮬레이션과 외부 효과

결제, 메시지 발송, 공개 게시, 배포, 실제 삭제처럼 외부 효과가 있는 단계는 프로젝트의 테스트 환경, 명확한 시뮬레이션, 설명을 고려한다. 사용자가 이미 승인한 실행 범위를 따르며 튜토리얼 구현 요청만으로 실제 외부 실행 권한을 추가하지 않는다.

시뮬레이션은 실제 검증 규칙과 상태 표현을 가능한 한 재사용한다. 시뮬레이션의 결과로 실제 영수증·발송·처리 완료가 발생했다고 주장하지 않는다. 재시작 시 같은 외부 요청을 자동 재전송하지 않는다.

### 실제 컴포넌트를 사용하는 격리 체험

별도 연습 화면이 필요하면 실제 화면 컴포넌트에 데모 데이터 공급자와 로컬 실행 콜백을 연결한다. 실제 입력 검증·팝업·결과 표현을 재사용하고, 단순한 no-op 저장 때문에 성공 결과를 체험할 수 없게 만들지 않는다. 로컬 성공·실패 상태를 일관되게 재현한다. 버튼만 막는 것으로 끝내지 않고 폼 제출·단축키·확인 모달이 같은 연습용 실행 경로를 사용하는지 확인한다.

iframe은 격리된 화면이나 기기 프레임이 유용할 때만 선택한다. 강조·측정 코드를 대상과 같은 document에 두면 좌표계 혼동을 줄일 수 있다. 바깥에 표시해야 한다면 iframe의 위치·스크롤·스케일을 함께 변환한다. 다른 origin의 DOM에 직접 접근할 수 있다고 가정하지 않는다. iframe만으로 서버 쓰기가 막히지는 않으므로 실제 실행 경로를 분리한다.

자동 시범은 복잡한 조작을 먼저 보여줄 필요가 있을 때 선택한다. 일시정지·다시 보기·종료를 제공하고, 자동 시범 완료를 사용자의 직접 수행 완료로 기록하지 않는다. 직접 연습 구간에서는 필요한 입력을 허용한다. 이 부분은 [embedded-uiux-walkthrough](https://github.com/Tanwyhang/embedded-uiux-walkthrough/blob/15086255d0c5dfa52fcc8c6f6ca6b177a1154423/skills/embedded-uiux-walkthrough/SKILL.md)의 화면 재사용·좌표계 패턴을 각색했다.

## 재시작

학습 목표를 다시 수행할 수 있는 준비 상태를 만든다. 화면만 첫 단계로 돌려놓고 이미 완료된 데이터 때문에 즉시 모든 단계를 통과하게 하지 않는다.

다만 결과 관찰을 다시 하는 항목은 같은 데이터를 그대로 사용할 수 있다. 새로운 자원을 생성해야 하는 연습은 필요한 범위만 새로 만들고, 이전 연습 자원의 유지·정리 정책을 따른다.

영구적인 진도 저장은 별도 요구가 있을 때 구현한다. 지원한다면 학습 정의 버전, 데이터 가용성, 현재 권한을 확인하고 복구할 수 없는 중간 단계를 무조건 재개하지 않는다.
