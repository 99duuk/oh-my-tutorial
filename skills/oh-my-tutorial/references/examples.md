# 도메인별 적용 사례

이 문서의 기능·역할·규칙은 가상의 예시다. 대상 프로젝트에 그대로 존재한다고 가정하지 않는다. 가까운 사례의 판단 방법만 참고하고 실제 코드·문서로 목표와 완료 조건을 다시 정한다.

필요한 사례만 읽는다: 예약 등록, 주문 처리, 분석 조회, 문서 결재, 편집 도구.

## 예약 등록: 입력·검증 중심

### 요청

“예약 관리에서 처음 쓰는 직원이 예약을 등록하고 시간을 바꾸는 방법을 익히게 해줘.”

### 조사할 사실

예약 가능 시간, 필수 입력, 중복 검증, 생성·변경 함수, 성공 결과, 일정 표시, 알림 발송 여부. 실제 코드가 시간 충돌을 허용한다면 임의로 충돌 금지를 업무 규칙으로 설명하지 않는다.

### 학습 구성 예시

목표: 빈 시간에 연습 예약을 만들고 변경 결과를 확인한다.

| 단계 | 배우는 내용 | 수행·완료 근거 |
|---|---|---|
| 시작 | 어떤 작업을 연습하는지 | 설명 확인 |
| 시간 선택 | 가능한 시간을 찾는 방법 | 선택한 시간이 입력 화면에 반영 |
| 정보 입력 | 필수 정보의 의미 | 실제 입력과 기존 검증 활용 |
| 등록 | 예약을 생성하는 방법 | 생성 성공 + 연습 예약 식별자 |
| 결과 확인 | 일정에서 예약을 찾는 방법 | 생성한 예약을 표시·열기 |
| 변경 | 기존 예약을 수정하는 방법 | 같은 예약의 시간 변경 성공 |
| 마무리 | 실제 작업의 위치와 주의점 | 실제 메뉴 경로 안내 |

연습 방식: 격리된 임시 예약이나 기존 데모를 우선 고려한다. 고객 알림이 발생한다면 테스트 환경·시뮬레이션을 검토한다.

실패·재시도: 필수값 누락이나 중복 검증 실패는 같은 단계에 남긴다. 종료 후 늦은 생성 결과가 도착하면 새 학습을 진행시키지 않는다. 만들어진 연습 자원은 소유권 정책에 따라 처리한다.

이 사례의 포인트는 클릭 순서보다 입력 검증, 생성 성공, 같은 대상의 변경을 연결하는 것이다.

## 주문 처리: 업무 상태 전환 중심

### 요청

“주문 접수부터 출고 준비까지 신입 직원이 따라 하게 해줘.”

### 조사할 사실

실제 상태 전이, 직원 권한, 품목·재고 확인 기준, 처리 접수와 완료의 차이, 취소 가능 범위, 외부 출고 연동. 코드에 없는 업무 절차를 만들어 넣지 않는다.

### 학습 구성 예시

목표: 처리 가능한 연습 주문을 확인하고 출고 준비 상태로 전환한다.

| 단계 | 배우는 내용 | 수행·완료 근거 |
|---|---|---|
| 주문 찾기 | 상태별 목록 사용 | 연습 주문과 조건이 일치하는 목록 |
| 상세 확인 | 처리 전 확인할 정보 | 필요한 항목 조회와 해설 |
| 접수 | 실제 상태 전환 | 해당 주문의 접수 성공 |
| 처리 대기 | 접수와 완료의 차이 | 해당 작업의 실제 상태 |
| 결과 확인 | 다음 담당자가 볼 상태 | 연습 주문의 출고 준비 상태 확인 |

분기: 실제 제품이 지원한다면 재고 부족 주문은 별도 안내 경로가 될 수 있다. 첫 입문 흐름에 모든 예외를 강제로 넣지 않는다.

연습 방식: 실제 출고를 유발하지 않는 연습 주문이나 테스트 연동을 선택한다. 요청 버튼을 눌렀다는 이유로 출고 완료를 선언하지 않는다.

이 사례의 포인트는 서비스가 정의한 상태와 역할, 비동기 처리 의미를 보존하는 것이다.

## 분석 조회: 관찰·비교 중심

### 요청

“분석 대시보드에서 원하는 기간과 지역을 조회하고 이전 기간과 비교하도록 튜토리얼을 만들어줘.”

### 조사할 사실

필터 의미, 조회 실행 시점, 데이터 갱신 상태, 비교 기능, 지표 정의, 결과가 없는 경우, 응답과 조건의 대응. 차트가 있다는 이유만으로 캔버스 조작을 학습 대상으로 삼지 않는다.

### 학습 구성 예시

목표: 지정 조건으로 조회하고 같은 기준의 두 기간 결과를 비교한다.

| 단계 | 배우는 내용 | 수행·완료 근거 |
|---|---|---|
| 지표 이해 | 숫자가 의미하는 것 | 확인된 지표 정의를 설명 |
| 조건 지정 | 조회 범위 좁히기 | 지정 기간·지역 선택 |
| 조회 | 선택 조건의 결과 가져오기 | 해당 조건의 최신 응답 반영 |
| 비교 설정 | 비교 기준 맞추기 | 제품의 실제 비교 설정 반영 |
| 차이 확인 | 두 결과를 읽는 방법 | 비교 결과와 해설 확인 |
| 마무리 | 실제 분석 시작 위치 | 메뉴와 조건 초기화 방법 안내 |

연습 방식: 조회 전용 예시 데이터나 기존 데이터의 조건을 사용한다. 데이터 생성·삭제를 추가할 필요가 없다.

실패·재시도: 이전 조건의 느린 응답을 현재 조건의 성공으로 인정하지 않는다. 결과가 없는 경우에는 빈 결과의 의미를 설명하거나 예시 조건으로 다시 시도한다.

이 사례의 포인트는 조회 맥락과 결과의 일치, 비교 기준, 해설이다. 단순 클릭만으로 사용자가 차이를 이해했다고 주장하지 않는다.

## 문서 결재: 역할과 분기 중심

### 요청

“문서 작성부터 결재 요청까지 배우고, 승인자는 어디서 검토하는지 알 수 있게 해줘.”

### 조사할 사실

작성자·승인자 역할, 필수 항목, 결재 경로 규칙, 요청·검토 상태, 실제 알림과 발송. 역할별 화면을 현재 사용자 권한으로 접근할 수 있는지 확인한다.

### 학습 구성 예시

- 작성자: 연습 문서 준비 → 필수 내용 입력 → 경로 지정 → 요청 접수 확인 → 대기 상태 확인.
- 승인자: 검토 목록 → 문서와 의견 확인 → 허용된 연습 처리 → 결과 상태 확인.

실제 권한이 없으면 해당 역할의 체험을 시작 가능하게 만들지 않는다. 개념 설명이나 격리된 역할 시뮬레이션이 필요하면 실제 권한과 구분한다.

“이전 단계 보기”가 실제 요청 취소나 재발송이 되어서는 안 된다. 발송이 있다면 학습 재시작이 중복 발송을 일으키지 않게 한다.

이 사례의 포인트는 사용자별 학습 가능 범위와 업무 분기다.

## 편집 도구: 모드·조작 중심

### 요청

“편집기에서 선택·이동·적용을 직접 해보며 익히게 해줘.”

### 조사할 사실

모드 의미, 실제 입력 방식, 변경 적용 시점, 원본·편집 상태 소유권, undo, 저장, 비동기 처리, 결과 표시. 특정 도구의 동작을 모든 편집기에 가정하지 않는다.

### 학습 구성 예시

도구 선택 → 작은 과제 수행 → 결과 확인 → 도구 종료 또는 다음 기능으로 이동. 변경이 종료 시 반영되는 도구라면 적용 시점까지 학습에 포함한다. 즉시 반영되는 도구에는 불필요한 종료·적용 단계를 만들지 않는다.

연습 방식: 준비된 사본이나 현재 작업을 선택하고 유지·원복 정책을 정한다. 현재 작업의 전체 상태를 덮어써 원복하지 않는다.

드래그가 있으면 출발·이동·도착이 모두 가능해야 한다. 모드 단축키가 있으면 안내 키와 충돌하지 않게 한다.

이 사례에서만 모드, 드래그, 필요하면 캔버스·프레임을 다룬다. 다른 도메인의 공통 학습 모델에는 이를 요구하지 않는다.

## 다른 도메인으로 옮길 때

같은 단계 제목을 치환하는 대신 다음을 다시 작성한다.

1. 사용자 결과와 실제 업무 규칙.
2. 준비 조건과 핵심 개념.
3. 사용자에게 의미 있는 과제.
4. 성공의 근거와 결과 피드백.
5. 데이터·외부 효과·종료 정책.
6. 해당 기술 환경에서 가장 작은 연결 방식.

공통으로 재사용하는 것은 이 판단 과정과 학습 원리다.
