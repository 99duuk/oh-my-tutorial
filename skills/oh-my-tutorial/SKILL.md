# oh-my-tutorial

사용자가 지정한 서비스·메뉴·업무의 사용법을 맥락 이해, 직접 수행, 결과 확인을 통해 익히는 튜토리얼을 만든다. RPG의 학습 순서와 피드백 방식을 적용한다. 게임 외형과 보상은 선택 사항이다.

## 요청과 범위

- 대상 프로젝트, 메뉴·기능, 대상 사용자, 학습 목표를 요청과 실제 자료에서 파악한다. 짧은 요청이어도 조사 가능한 구현 사항을 사용자에게 다시 설명받지 않는다.
- 구현 요청이면 분석·설계·구현·검증까지 수행한다. 명세·검토 요청이면 해당 산출물만 만든다. 기존 튜토리얼 수정 요청이면 현재 구조를 먼저 확인하고 필요한 부분을 개선한다.
- 메뉴 요청에는 학습 항목 선택, 종료 후 복귀, 다시 시작할 수 있는 진입점을 포함한다. 기존 메뉴·권한 체계를 활용한다.
- 사실로 확인할 수 없는 업무 판단 중 결과에 큰 영향을 주는 것만 질문한다. 일반적인 구현 선택마다 승인을 기다리지 않는다. 발견한 사실과 가정을 구분한다.
- 기존 프로젝트의 언어·스타일·명령·기술 구조를 따른다. 이 스킬은 별도 도구, 프레임워크, 다른 스킬, 원본 사례 저장소를 요구하지 않는다.

## 공통 원칙

1. **사용자 목표에서 시작한다.** 화면 배치 순서나 모든 버튼 목록을 학습 순서로 삼지 않는다.
2. **필요한 순간에 가르친다.** 현재 목표, 행동의 이유, 할 일, 확인할 결과를 연결한다. 독립적인 과제를 한 단계에 몰아넣지 않는다.
3. **의미 있는 성공을 경험하게 한다.** 기능에 맞춰 관찰·선택·입력·실행·비교를 사용한다. 적합한 기능에서는 사용자가 직접 수행해야 진행하는 체험을 포함한다.
4. **실제 성공에 근거한다.** 버튼 클릭이나 요청 시작만으로 성공을 선언하지 않는다. 학습 목표에 맞는 결과·상태·성공 이벤트를 확인한다. 검수 가능한 근거 없이 학습 이해를 자동 판정했다고 말하지 않는다.
5. **기존 서비스에 연결한다.** 실제 화면과 업무 규칙을 우선 활용한다. 격리나 시뮬레이션이 필요하면 차이를 명확히 한다. 단순한 안내 카드만 만들고 기능 연결을 완료했다고 하지 않는다.
6. **중단과 재학습을 설계한다.** 종료, 재시도, 재시작, 늦은 응답, 임시 상태 정리를 필요한 범위에서 다룬다. 설명으로 돌아가기와 작업 원복은 별개이다.
7. **프로젝트에 맞춰 구현한다.** 학습 내용·진행·표현·기능 연결·연습 환경의 책임을 구분하되 파일 수, 상태 관리 도구, 공통 엔진을 강제하지 않는다.
8. **도메인 의미를 보존한다.** 특정 편집기의 캔버스·프레임·모드나 샘플 데이터 구조를 공통 전제로 삼지 않는다. 단어만 치환하지 말고 해당 서비스의 목표와 성공 조건을 새로 도출한다.

## 실행 흐름과 참고 문서

참고 문서는 필요한 단계에 읽는다. 처음부터 모두 읽거나 예제 전체를 구현하지 않는다.

### 1. 조사하고 학습 목표를 정한다

관련 화면, 실제 기능, 상태 전이, API, 문서, 기존 안내, 검증 명령을 조사한다. 범위·근거·미확정 사항과 학습 항목 초안을 정리한다.

[discovery-and-learning-design.md](references/discovery-and-learning-design.md)를 읽고 목표와 대표 경로를 설계한다. 도메인 적용 판단이 어려우면 [examples.md](references/examples.md)에서 가까운 사례만 읽는다.

### 2. 단계와 연습 환경을 설계한다

대표 작업 따라 하기, 기능 상세 안내, 현재 맥락의 연습 중 필요한 구성을 선택한다. 각 단계의 준비 조건, 수행할 일, 완료 근거, 결과 피드백, 복구 방법을 정한다.

체험 단계가 있으면 [step-and-completion-contracts.md](references/step-and-completion-contracts.md)를 읽는다. 데이터·상태 변경 또는 준비 작업이 있으면 [practice-environment-and-lifecycle.md](references/practice-environment-and-lifecycle.md)를 읽고 변경 소유권과 종료 정책을 정한다.

### 3. 실제 기능에 연결해 구현한다

[presentation-and-integration.md](references/presentation-and-integration.md)를 읽고 기존 구조에 맞는 안내와 연결 방식을 선택한다. 대표 학습 경로를 끝까지 연결해 가설을 확인한 뒤 요청 범위 전체를 완성한다. 대표 경로만 만든 것을 전체 완료로 보고하지 않는다.

공개 도구를 재사용하거나 웹 안내의 외형·대상 탐색을 보강할 때는 [open-source-patterns.md](references/open-source-patterns.md)를 읽는다. 적용 조건, Driver.js 연결 예시, 선택적인 브라우저 대상 탐색 코드와 출처가 있다. 라이브러리 도입은 필수가 아니다.

작동하는 튜토리얼 메뉴, 학습 내용, 진행 처리, 실제 기능 연결, 필요한 연습 환경을 구현한다. 불필요한 데이터베이스·관리자 편집기·새 의존성을 추가하지 않는다.

### 4. 검증하고 결과를 보고한다

[implementation-and-validation.md](references/implementation-and-validation.md)를 읽고 학습 목표와 실패 가능성에 맞는 검증을 수행한다. 정적 검사, 실제 UI 실행, 시뮬레이션 검증을 구분해서 보고한다.

보고에는 진입 방법, 배울 수 있는 범위, 연습 변경 처리, 수행한 검증, 실제로 남은 제약을 포함한다. 코드만 확인하고 브라우저 체험까지 검증했다고 하지 않는다.

## 완료 기준

아래는 구현 요청의 기준이다. 명세·검토만 요청받았으면 해당 범위의 목표·완료 근거·연결 방법·복구 정책·검증 계획을 산출물로 확인하고, 실행하거나 구현한 것으로 보고하지 않는다.

- 학습 메뉴에서 목표에 맞는 항목을 고르고 시작·종료·재시작할 수 있다.
- 설명과 실제 기능이 일치하며, 적합한 기능에는 직접 수행과 결과 확인이 연결돼 있다.
- 완료 조건과 피드백이 목표에 맞고 실패를 성공으로 처리하지 않는다.
- 관련 준비 실패·중단·재시도 경로가 있으며 종료 후 기존 서비스를 정상 사용한다.
- 요청 범위를 구현했고, 기존 기능을 불필요하게 바꾸지 않았다.
- 다른 도메인에 원본 저장소·이전 대화·특정 기술 스택 없이 적용할 수 있다.

진도 영구 저장, 보상, 학습 분석, 다국어, 단계 관리자, 자동 첫 실행은 사용자 요청이나 기존 제품 요구가 있을 때 확장한다. 호출만으로 배포·발송·결제 같은 외부 실행의 권한이 추가되지는 않는다.
